# دليل تصميم وتبسيط واجهة SmartATS

> **طريقة الاستخدام:** ألصق هذا الملف (أو الأقسام 1 و2 و3 و9 على الأقل) في بداية أي محادثة جديدة، ثم اكتب المطلوب. أي تعديل على الواجهة يجب أن يلتزم بهذا الدليل.

---

## 1. فلسفة التصميم (5 مبادئ)

1. **سؤال واحد لكل شاشة:** كل صفحة تجيب عن سؤال واحد واضح («من هم أفضل المرشحين؟»، «ما حالة العروض؟»).
2. **إجراء رئيسي واحد:** في كل صفحة وكل بطاقة زر واحد `type="primary"`. الباقي ثانوي أو داخل قائمة «⋯».
3. **الإفصاح التدريجي:** المبتدئ يرى الأساسي فقط، والتفاصيل المتقدمة داخل `expander` أو وضع «متقدم».
4. **الأرقام لا تأتي وحدها:** أي درجة مطابقة تُعرض مع سبب (نقاط قوة / فجوات). هذا مبدأ أساسي في المشروع.
5. **الذكاء الاصطناعي يقترح والإنسان يقرر:** نصوص الواجهة تقول «مقترح» و«تقدير آلي»، ولا تقول «قرار» أو «تم رفض».

---

## 2. قواعد ثابتة (لا استثناء)

| # | القاعدة |
|---|---|
| 1 | لا CSS داخل الصفحات. كل الأنماط في `ui/theme.py` وتُحقن مرة واحدة من `app.py` |
| 2 | لا ألوان مكتوبة يدوياً (`#22c55e`…) في الصفحات. فقط من `theme.COLORS` |
| 3 | لا منطق أعمال ولا استعلامات في `views/`. فقط عبر `services/` |
| 4 | كل نص ظاهر للمستخدم بالعربية، وأسماء الحالات الداخلية (`Shortlisted`…) تُترجم عبر قاموس واحد `STAGE_LABELS` |
| 5 | كل ثابت رقمي في `core/constants.py` (لا أرقام سحرية) |
| 6 | كل عملية كتابة تمر عبر `run_action(...)` الذي يعرض الخطأ ويمسح الكاش ويعمل `rerun` |
| 7 | كل مفتاح `key=` فريد وله بادئة الصفحة (`jobs_`, `iv_`, `of_`) |
| 8 | لا `expander` داخل `expander`، ولا `dialog` داخل `dialog` |
| 9 | الأزرار الجديدة التي تكتب بيانات تُحترم فيها صلاحية القراءة فقط (`ui/readonly.py`) |

## 3. نظام التصميم (Design Tokens)

### 3.1 الألوان الدلالية
اللون يدل على **معنى** وليس زينة.

```python
# ui/theme.py
COLORS = {
    "primary":  "#2563eb",  # الإجراء الرئيسي، الروابط، العنصر المحدد
    "success":  "#16a34a",  # مكتمل، مطابقة قوية، مقبول
    "warning":  "#d97706",  # يحتاج انتباه، متوسط
    "danger":   "#dc2626",  # رفض، فجوة، خطأ
    "neutral":  "#64748b",  # جديد، مسودة، غير مهم
    "info":     "#3b82f6",  # قيد التنفيذ
}

# مراحل التوظيف: لون واحد لكل مرحلة في كل الصفحات
STAGE_COLORS = {
    "New": "#64748b", "Screening": "#3b82f6", "Shortlisted": "#d9a21b",
    "Interview": "#f59e0b", "Offer": "#d9487a", "Hired": "#16a34a", "Rejected": "#b91c1c",
}
STAGE_LABELS = {
    "New": "جديد", "Screening": "الفرز", "Shortlisted": "القائمة المختصرة",
    "Interview": "المقابلة", "Offer": "العرض", "Hired": "التعيين", "Rejected": "مرفوض",
}

# درجة المطابقة: عتبتان فقط في كل المشروع
SCORE_GOOD, SCORE_MID = 75, 50   # أخضر ≥75، برتقالي ≥50، أحمر أقل

def score_color(value: float) -> str:
    if value >= SCORE_GOOD: return COLORS["success"]
    return COLORS["warning"] if value >= SCORE_MID else COLORS["danger"]
```

> **ملاحظة اتساق:** `jobs` تعتبر المطابقة العالية 80 (`MATCH_HIGH_THRESHOLD`) وصفحات أخرى 75. وحّدها في ثابت واحد.

### 3.2 الطباعة والمسافات
| العنصر | الحجم | الوزن |
|---|---|---|
| عنوان الصفحة | `st.header` | افتراضي |
| عنوان بطاقة / قسم | 1.0 – 1.1rem | 700 |
| نص عادي | 0.85 – 0.9rem | 400 |
| نص ثانوي / تعليق | 0.72 – 0.78rem | 400، شفافية .65 |
| رقم مؤشر كبير | 1.6 – 1.7rem | 700 |

- **المسافات:** وحدة أساسية 4px. استخدم فقط: 4 / 8 / 12 / 16 / 24.
- **الزوايا:** 12px للبطاقات، 999px للشارات والأزرار الصغيرة، 8px للحقول.
- **الحدود:** `1px solid rgba(128,128,128,.25)` وخلفية `rgba(128,128,128,.06)` (تعمل في الوضعين الفاتح والداكن).

### 3.3 الاتجاه (RTL)
- الحاوية الرئيسية `direction: rtl; text-align: right`.
- استخدم الخصائص المنطقية: `margin-inline-start`, `padding-inline-end`, `border-inline-start` بدل `left/right`.
- الأسهم: «التالي» ← و«السابق» → (عكس الإنجليزية). النصوص الإنجليزية (أسماء مهارات، أكواد) تبقى LTR داخل `<bdi>`.

## 4. المكونات الموحدة

كل مكون يُكتب **مرة واحدة** في `ui/components.py` ويُستدعى من كل الصفحات. الدوال المكررة اليوم وتُدمج:

| المكون | الدالة الموحدة | الموجود مكرراً في |
|---|---|---|
| شارة حالة | `badge(text, color)` | candidate_profile, interviews, offers, jobs |
| حلقة / شريط درجة | `score_ring(v)`, `score_bar(v)` | matching, interviews, job_candidates, org |
| صورة رمزية | `avatar(candidate)` | matching, offers, candidates |
| شريحة مهارة | `chip(text)` | jobs, candidate_profile, interviews |
| بطاقة مؤشر | `kpi_card(icon, label, value, sub)` | jobs, offers, org |
| حالة فراغ | `empty_state(...)` (موجودة) | استخدمها في كل صفحة |
| تنفيذ إجراء | `run_action(fn, msg)` | offers, interviews, org, jobs |
| مسح الكاش | `invalidate_all()` | offers, job_candidates, pipeline, jobs |
| تنظيف نص | `clean_line(text)` | matching, job_candidates, org |
| تقسيم قائمة | `split_items(raw)` | jobs, candidate_profile |

### مثال: `run_action` الموحد
```python
def run_action(action, success: str, rerun: bool = True) -> bool:
    try:
        with get_db_session() as session:
            action(session)
    except SmartATSError as exc:
        st.error(str(exc))
        return False
    invalidate_all()
    st.toast(success)
    if rerun:
        st.rerun()
    return True
```

## 5. قالب الصفحة الموحد

كل صفحة تتبع **نفس الهيكل** من الأعلى للأسفل:

```
┌──────────────────────────────────────────────┐
│ 1. العنوان + سطر شرح (caption) + الإجراء الرئيسي │
├──────────────────────────────────────────────┤
│ 2. المؤشرات (3–5 بطاقات كحد أقصى)               │
├──────────────────────────────────────────────┤
│ 3. شريط بحث + فلاتر (صف واحد)                   │
├──────────────────────────────────────────────┤
│ 4. المحتوى الرئيسي (جدول/بطاقات) + لوحة جانبية  │
├──────────────────────────────────────────────┤
│ 5. تحليلات ثانوية (داخل expander أو أسفل)       │
└──────────────────────────────────────────────┘
```

```python
def render() -> None:
    page_header("💼 الوظائف", "إدارة الشواغر والمتطلبات", primary=("➕ إنشاء وظيفة", _create_dialog))
    data = _load()
    if not data:
        empty_state(...)          # دائماً حالة فراغ تقترح الخطوة التالية
        return
    render_kpis(data["kpis"])
    filters = render_filters(data)
    render_main(filters)
```

**قواعد القالب:**
- حالة الفراغ **تقترح الخطوة التالية** بزر، ولا تكتب «لا توجد بيانات» فقط.
- المؤشرات لا تزيد عن 5 في الصف.
- الصفحة التي يزيد طولها عن شاشتين تُقسم بتبويبات (`st.tabs`) بحد أقصى 4 تبويبات.
- الترتيب الثابت للتبويبات: الأهم أولاً، والإدارة / الإعدادات / الحذف **آخراً**.

## 6. أنماط التبسيط للمبتدئين

### 6.1 وضع «مبسّط / متقدم»
مفتاح في الشريط الجانبي `st.session_state["ui_mode"]` بقيمتين `simple` و`advanced`.

| العنصر | مبسّط | متقدم |
|---|---|---|
| مرشح: تبويبات الملف | نظرة عامة، الخبرات، الوظائف المناسبة | + تحليل AI، التفاصيل، التعديل |
| وظائف: النموذج | العنوان، القسم، الخبرة، المهارات | + الراتب، المستوى، أوزان، رسوم |
| مقابلات: التبويبات | المقابلة فقط | + أسئلة المقابلة، الإدارة |
| مطابقة: شرح الدرجة | نسبة + 3 نقاط قوة + فجوات | + تفصيل كل معيار |
| تصدير | CSV / Excel | + Excel منظّم |

```python
def advanced() -> bool:
    return st.session_state.get("ui_mode") == "advanced"
```

### 6.2 «الخطوة التالية» دائماً ظاهرة
كل بطاقة مرشح تعرض **زراً واحداً** يقترح الإجراء التالي حسب المرحلة (موجود في `_NEXT_ACTIONS` ويُوحَّد في مصدر واحد):

`جديد ← بدء الفرز ← قائمة مختصرة ← جدولة مقابلة ← إنشاء عرض ← متابعة العرض`

### 6.3 تقليل الأزرار
- أكثر من 3 أزرار في بطاقة ← انقل الثانوية إلى `st.popover("⋯")`.
- أي زر **مدمّر** (حذف، رفض) يكون داخل `popover` ويتطلب تأكيداً (`checkbox`) ويكون لونه عادياً لا `primary`.
- لا تضع زرين متجاورين بنفس الأهمية البصرية.

### 6.4 لغة الواجهة
| بدل | استخدم |
|---|---|
| Embedding / Semantic | «تشابه عام» |
| Pipeline | «مسار التوظيف» |
| Match Score | «نسبة المطابقة» |
| Shortlist | «القائمة المختصرة» |
| «لا يملك المهارة» | **«غير موثّقة في السيرة»** (قاعدة أساسية، لا تُخالف) |

### 6.5 التنقل
اليوم 13 عنصراً في قائمة واحدة. التجميع المقترح بعناوين فرعية (`st.caption` بين مجموعات الراديو):

```
🏠 الرئيسية
── التوظيف ──   📄 رفع سيرة · 👥 المرشحون · 💼 الوظائف · 🎯 المطابقة
── المتابعة ──  🧭 المسار · 🗓️ المقابلات · 📑 العروض
── المنظمة ──   🏢 الهيكل · 📊 لوحة المعلومات · 📈 التقارير
── النظام ──    ❓ المساعدة · 🔑 حسابي · 👥 المستخدمون (للأدمن)
```

## 7. تفاصيل التفاعل (UX)

| الحالة | السلوك الموحد |
|---|---|
| نجاح عملية | `st.toast("... ✅")` ثم `rerun` |
| فشل عملية | `st.error(رسالة عربية مفهومة)` بدون تفاصيل تقنية |
| عملية طويلة (AI) | `st.spinner("جاري ...")` أو `st.progress` مع عدّاد |
| تحميل | لا شاشة بيضاء: استخدم `show_spinner` في الكاش |
| قائمة طويلة | ترقيم صفحات (10/25/50)، وليس تمريراً لا نهائياً |
| فلاتر | زر «🧹 مسح الفلاتر» دائماً ظاهر، وعدّاد «النتائج X من Y» |
| تعديل | نموذج `st.form` بزر حفظ واحد، لا حفظ تلقائي |
| حذف | تأكيد صريح + نص يوضح ماذا سيُحذف معه |
| لا نتائج بحث | اقتراح (جرّب وصفاً أبسط) + زر مسح الفلاتر |

**الكاش:** مدة 30 ثانية للقوائم. بعد كل كتابة `invalidate_all()`. زر «🔄 تحديث» في الصفحات الثقيلة.

## 8. إمكانية الوصول والجودة البصرية

- **التباين:** نص على خلفية ملونة (شارات، مراحل) لونه أبيض فقط إذا كانت الخلفية داكنة بما يكفي. اختبر الوضعين الفاتح والداكن.
- **لا تعتمد على اللون وحده:** مع كل لون أيقونة أو نص (✅ ⚠️ ❌).
- **حجم الهدف:** الأزرار الصغيرة داخل البطاقات لا تقل عن 2rem ارتفاعاً.
- **الأيقونات:** إيموجي واحد في بداية العنوان فقط، وليس في كل سطر.
- **الكثافة:** لا تضع أكثر من 3 أعمدة في الصف على شاشة 1080p، وأكثر من 6 فلاتر في شريط واحد.
- **الأرقام:** `1,250` بفاصل آلاف، والنسب `85%` بدون كسور إلا للدرجات (`87.5%`).
- **التواريخ:** صيغة واحدة `YYYY-MM-DD` (و`YYYY-MM-DD HH:MM` للأوقات)، والنسبي «منذ ساعتين» للنشاط الأخير فقط.

## 9. خطة التنفيذ على مراحل

> نفّذ مرحلة واحدة في كل محادثة، واختبر قبل الانتقال.

| المرحلة | العمل | الملفات | الاختبار |
|---|---|---|---|
| **A. الأساس** | إنشاء `ui/theme.py` (الألوان، CSS الموحد) و`ui/helpers.py`؛ حقن CSS مرة واحدة في `app.py` | جديدة + app.py | الصفحات تعمل كما هي |
| **B. دمج المكونات** | نقل `badge/avatar/score_ring/run_action/invalidate_all/clean_line/split_items` | كل `views/` | حذف التكرار، لا تغيير بصري |
| **C. توحيد الألوان** | استبدال كل لون يدوي بـ `COLORS`/`STAGE_COLORS`؛ دمج قواميس `_STAGE_LABELS` | matching, pipeline, offers, interviews, candidate_profile | نفس الألوان لكل مرحلة |
| **D. قالب الصفحة** | `page_header()` وتطبيقه على كل صفحة | كل `views/` | رأس موحد |
| **E. التبسيط** | وضع مبسّط/متقدم، نقل الأزرار الثانوية لـ `popover`، إخفاء التبويبات المتقدمة | interviews, jobs, candidate_profile أولاً | مبتدئ يكمل المسار |
| **F. التنقل** | تجميع القائمة، إضافة صفحة المساعدة | navigation.py, app.py | الصلاحيات تعمل |
| **G. تنظيف** | حذف الميت (`dashboard/reports` إن لم تُستخدم، `_render_study_tab` غير المربوطة)، وتصحيح `PHOTO_SEARCH_MAX_views` | متفرقة | لا أخطاء استيراد |

**ترتيب الصفحات من الأكثر فائدة للتبسيط:** `interviews` ← `jobs` ← `candidate_profile` ← `matching` ← `offers` ← `organization` ← `candidates` ← `home`.

## 10. قائمة فحص قبل تسليم أي تعديل

- [ ] لا CSS جديد داخل الصفحة (إلا إضافة في `theme.py`)
- [ ] لا لون مكتوب يدوياً
- [ ] صفحة واحدة = إجراء رئيسي واحد
- [ ] حالة فراغ تقترح خطوة تالية
- [ ] كل نص عربي وواضح، ولا مصطلح تقني
- [ ] «غير موثّق» وليس «لا يملك»
- [ ] الإجراءات المدمّرة بتأكيد داخل `popover`
- [ ] الكاش يُمسح بعد الكتابة
- [ ] `key=` فريدة ببادئة الصفحة
- [ ] يعمل في الوضعين الفاتح والداكن
- [ ] يعمل لمستخدم Viewer (الأزرار معطّلة بدون خطأ)
- [ ] لم تُلمس القاعدة ولا ملفات `data/` و`uploads/`
- [ ] جُرّب على نسخة **dev** وليس النسخة الحية
